### 语音转字幕 Bug 修复（两轮排查）

#### 第一轮修复（未完全解决问题）

**问题**：第一次处理有进度但最终失败，第二次立即报错"文件中未检测到语音内容"

**发现**：`recognizer.recognitionTask(with:)` 返回的 `SFSpeechRecognitionTask` 没有被持有引用，ARC 立即释放

**修复**：
1. 用 `var speechTask: SFSpeechRecognitionTask?` 持有 task 引用
2. 添加 `hasResumed` 标志位防止 continuation 重复 resume 崩溃
3. 识别完成但 `formattedString` 为空时抛 `.noSpeechDetected`

#### 第二轮修复（找到根因）

**问题**：第一轮修复后仍然报错，用户要求全面彻查

**根因**：`extractAudio()` 函数中 AVAssetReader/AVAssetWriter 的竞态条件

```swift
// 问题代码：
writerInput.requestMediaDataWhenReady(on: queue) { ... }  // 后台队列异步执行
writer.finishWriting {}  // 主线程立即调用，不等待后台写入！

// finishWriting 在数据写入前就告诉 writer "结束了"
// → 提取出的 M4A 是空文件 → SFSpeechRecognizer 识别不到语音
```

`requestMediaDataWhenReady` 在后台队列上执行数据写入，但 `finishWriting` 在主线程上立即调用，两者之间存在竞态。大多数情况下 `finishWriting` 在数据写入之前执行，导致提取的音频文件为空。

**为什么第一次"有时"能跑**：取决于 GCD 调度时机，后台队列偶先执行完写入，`finishWriting` 晚到，此时文件有内容。但这种幸运窗口极窄。

**彻底修复**：用 `AVAssetExportSession` 重写 `extractAudio()`：
- 废弃 AVAssetReader/AVAssetWriter（存在竞态）
- 改用 `AVAssetExportSession(presetName: AVAssetExportPresetAppleM4A)`
- 用 `withCheckedContinuation` 替代 semaphore 等待导出完成
- 函数改为 `async throws`

### 字幕断句智能合并优化

**问题**：SFSpeechRecognizer 每个 segment 通常只包含 1~2 个词，逐段导出导致字幕碎片化——单字/单词独占一行、不到1秒就换行、阅读体验极差。

**方案**：新增 `mergeSegments()` 函数，在后处理阶段智能合并细粒度片段。

**合并规则（满足任一即切割）**：
1. 上一段以强标点结尾（。！？.!?）—— 语句自然结束
2. 当前批次累积超过 4 秒 —— 避免单条字幕过长
3. 两段之间间隔 > 0.5 秒 —— 明显停顿，换句
4. 批次 ≥ 2 秒 + 弱标点或小停顿 —— 句子够长且有自然断点

**效果**：
- 单条字幕 2~5 秒，完整显示一个自然句
- 不会出现单字、单词独占一行
- 时间轴与原始识别结果保持对齐
- 中英文均适用（中文直接拼接，英文片段自带空格）

**涉及文件**：[SpeechToTextService.swift](../RuiTuOfficeMaster/Shared/Services/SpeechToTextService.swift) — 新增 `mergeSegments()` + 修改 `transcribe()` 中的条目构建逻辑

### 人声增强/降噪输出无法播放 Bug 修复

**问题**：人声增强和降噪处理后的音频文件无法正常播放。

**根因（两个致命 Bug）**：

**Bug 1 — `player.play()` 缺失**：

```swift
// 原代码：
player.scheduleFile(audioFile, at: nil)
// ❌ 没有 player.play()！播放器不启动，不读取数据

// engine.renderOffline() 从源头拉数据 → 播放器不播放 → 拉不到 → 
// 所有渲染都返回 .insufficientDataFromInputNode → 输出空/垃圾数据
```

`scheduleFile` 只是把文件排入播放队列，**不启动播放**。在离线渲染模式下，引擎需要从源头节点拉数据，播放器不播放就没有任何音频流经 EQ 节点，所有 `renderOffline` 调用都返回 `.insufficientDataFromInputNode`，输出文件实际为空或全是零值采样。

**Bug 2 — PCM 数据写入压缩格式容器**：

```swift
// 原代码：
let outputFile = try AVAudioFile(
    forWriting: outputURL,  // ← 可能是 xxx.m4a（AAC 压缩格式）
    settings: format.settings,  // ← PCM 设置
    ...
)
// ❌ PCM 音频数据 + M4A/AAC 容器 = 格式不匹配，无法播放
```

`format.settings` 是输入文件解码后的 PCM 格式（线性脉冲编码），但输出 URL 扩展名可能是 `.m4a`/`.aac`（需要 AAC 压缩编码）。把 PCM 数据写入压缩格式容器就像把生肉塞进压缩饼干包装——播放器按压缩格式解析，读到的却是原始数据，直接失败。

**修复方案**（[AudioProcessingService.swift](../RuiTuOfficeMaster/Shared/Services/AudioProcessingService.swift) `processWithEQ`）：

1. **加 `player.play()`**：`scheduleFile` 之后调用 `play()`，播放器开始读取数据 → 音频流经 EQ 节点 → 离线渲染拿到处理后的数据
2. **两步法解决格式 mismatch**：
   - **Step 1**：始终渲染到临时 CAF 文件（CAF 是 PCM 原生容器，不会 mismatch）
   - **Step 2**：CAF → 目标格式
     - PCM 格式（WAV/AIFF/CAF）：直接复制
     - 压缩格式（AAC/M4A）：用 `AVAssetExportSession` 转码
3. **`insufficientDataFromInputNode` 处理改进**：只在 buffer 有实际帧时才写入，避免末尾写入空数据

### 双语字幕翻译功能实现

**问题**：开启"生成双语字幕"后，实际没有执行翻译——`translatedText` 始终为 nil，导出字幕只有单语。

**根因**：
1. 原代码只有占位的 `prepareForTranslation()` 方法（仅清空 translatedText），从未调用翻译 API
2. `TranslationSession` 没有公开 init，必须通过 SwiftUI 的 `.translationTask()` 修饰符创建

**方案**：SwiftUI `.translationTask()` 桥接到 ViewModel

**架构**：
```
View (.translationTask)
  ↓ 注入 TranslationSession
ViewModel (setTranslationSession / waitForTranslationSession)
  ↓ 调用
SpeechToTextService (translateSubtitles(using:))
  ↓ 批量翻译
TranslationSession.translations(from:)
```

**改动清单**：

| 文件 | 改动 |
|------|------|
| [SpeechToTextService.swift](../RuiTuOfficeMaster/Shared/Services/SpeechToTextService.swift) | 添加 `import Translation`；`translateSubtitles` 改为接受 `TranslationSession` 参数；新增 `translatedFullText(from:)`；新增 `exportPlainTextBilingual()` |
| [MediaConversionViewModel.swift](../RuiTuOfficeMaster/Shared/ViewModels/MediaConversionViewModel.swift) | 添加 `import Translation`；新增 session 桥接属性（`_translationSession`、continuation）；`executeSpeechToText()` 在转录后执行翻译；`reExportSubtitles()` 支持双语纯文本 |
| [MediaConversionView.swift](../RuiTuOfficeMaster/macOS/Views/MediaConversion/MediaConversionView.swift) | 添加 `import Translation`；`body` 中条件使用 `.translationTask()`；纯文本预览区增加译文展示；可用性标注更新为 macOS 15.0 |

**翻译流程**：
1. `transcribe()` → 获取字幕条目（`translatedText: nil`）
2. 若开启双语 + macOS 15.0+：`waitForTranslationSession()` → `translateSubtitles(using:)` → 批量翻译
3. 同时生成 `translatedFullText`（译文拼接全文）
4. 导出时：SRT/VTT 每一条中文下方自动带英文翻译；纯文本输出原文+译文双段

**API 发现**：
- `TranslationSession` **没有公开 init**，只能由 `.translationTask()` 创建
- `Translation` 框架需要 macOS **15.0**（非之前记录的 14.4）
- `_Translation_SwiftUI` 提供 `View.translationTask()` 扩展，`import Translation` 后自动可用

## 备注
- SFSpeechRecognitionTask 必须被强引用持有，否则 ARC 释放会导致识别中断
- 不能在 recognitionTask 回调内调用 `task.cancel()`，会触发二次回调导致 crash
- AVAssetReader/AVAssetWriter 模式下 requestMediaDataWhenReady 与 finishWriting 存在竞态，不建议用于同步提取场景
- TranslationSession 无公开 init，必须通过 SwiftUI `.translationTask()` 创建
- Translation 框架需要 macOS 15.0+（非 14.4）
- `import Translation` 后 `_Translation_SwiftUI` 自动链接，提供 `View.translationTask()` 扩展

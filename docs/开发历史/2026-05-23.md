### 输入框无法输入 Bug 修复 ✅

**根因分析**：
1. `@Observable` + `@State` 组合下，自定义 `Binding(get:set:)` 在 setter 中同步执行副作用（如 `generatePreview()`），触发 `@Observable` 立即通知视图重评估，在 macOS 上打断了 TextField 的编辑事务
2. `$viewModel.property` 语法在没有 `@Bindable` 的情况下，Binding 身份不稳定，导致编辑状态丢失

**修复方案（3 个文件）**：

1. **FileRenameView**：所有自定义 Binding 的 setter 只做纯属性赋值，`generatePreview()` 移到 `.onChange(of:)` 修饰符中延迟执行
2. **ImageCompressionViewModel**：`updateAspectWidth`/`updateAspectHeight` 改为 `syncHeightFromWidth`/`syncWidthFromHeight`，不再设置主属性（由 Binding 处理），用像素差值 ≤2 的容差检查防止整数取整循环
3. **ImageProcessingView**：在需要绑定的计算属性中引入 `@Bindable var vm = viewModel`，所有 `$viewModel.xxx` 改为 `$vm.xxx`，纵横比 TextField 改用 `.onChange` 触发同步

**关键技术点**：
- `@Bindable`（iOS 17+/macOS 14+）是 `@Observable` 的配套包装器，提供稳定的 `$` 绑定投影
- `.onChange(of:)` 在属性变更后的视图更新周期中执行，不会干扰 TextField 的活跃编辑
- 容差检查（`abs(current - target) > 2`）防止整数取整导致的无限同步循环

**SwiftUI 输入框标准模板 & 架构规范（6 条规则）**：
1. ViewModel：`@Observable final class Xxx: @unchecked Sendable`
2. View 中必须用 `@Bindable var vm = viewModel`，绑定用 `$vm.xxx`（不可直接用 `$viewModel.xxx`）
3. Binding setter 必须纯赋值，副作用放 `.onChange(of:)`
4. 跨属性联动用 `.onChange` + 像素容差检查（`abs(current - target) > 2`）防循环
5. AppKit 调用（NSOpenPanel 等）必须加 `@MainActor`
6. 窗口级别焦点保障在 App 入口做一次（AppDelegate），不需要每个页面重复

## 2026-05-24 — 单个移除图片卡死 Bug 修复 ✅

### 问题现象
处理完图片后，点击列表中某张图旁边的 ❌ 叉号 → App 卡死。

### 根因分析
与"清空列表卡死"同根因：`removeImage()` 中 `results = []` 和 `selectedImages.remove(at:)` 在同一同步调用中执行，`resultsSection` 和 `selectedImages` 关联的多个条件区块在同一帧移除 → SwiftUI 布局引擎死锁。

### 修复方案（最终版）
**根因**：`removeImage()` 修改 `selectedImages` → 外层 `if !selectedImages.isEmpty` 变为 false → 4 个条件区块（imageFileList、compressionConfigSection、formatConversionSection、executeSection）加上 `resultsSection` 共 5 个区块在同一帧从 ScrollView/VStack 中移除 → 布局引擎死锁。

**前两次尝试失败**：
1. 两阶段异步（先清 results，下帧删图片）— 删最后一张图时仍然 3 个区块同时消失
2. 过滤 results 不清空 — 删最后一张图时仍然 4-5 个区块同时消失

**最终方案**：在视图层 **ImageProcessingView** 新增 `removeImageSafely()`：
- 只剩一张图时 → 直接 `viewModel = ImageCompressionViewModel()`（@State 整体替换，原子重建视图树，已证明有效）
- 还有多张图时 → `viewModel.removeImage(url:)`（仅行级变化，无区块增减）
- 同时简化 **ImageCompressionViewModel.removeImage()**：改为过滤单条结果而非清空全部（`results.removeAll { $0.originalURL == url }`）

**多张图片时删一张仍卡死（第三次尝试失败）**：
- 现象：单张图片 OK，多张图片处理完后删一张 → 卡死
- 原因 1：`removeImage()` 中 `clearMessages()` 将 `successMessage` 置 nil，executeSection 内的成功提示 Label 消失，与文件列表行、结果行变化叠加
- 原因 2：`ForEach(viewModel.results.indices, id: \.self)` 用索引做 ID，删除中间条目后索引全移位，SwiftUI diff 算法视图身份混淆

**最终完全修复（4 处改动）**：
1. **ImageProcessingView.removeImageSafely()**：只剩一张图时 @State 整体替换 ViewModel
2. **ImageCompressionViewModel.removeImage()**：移除 `clearMessages()` 调用（不触发 label 变化）
3. **ImageProcessingView resultsSection**：`ForEach(results, id: \.originalURL)` 替代 `ForEach(indices, id: \.self)`（稳定 ID）
4. 组合生效：多张图删一张只有行级变化，不会触发任何区块或 label 的移除 ✅

## 2026-05-24 下午 — 清空列表卡死 Bug 最终修复 ✅

### 问题现象
图片处理完成后，点击"清空列表"按钮 → App 自动跳转到历史记录页 → 整个 App 卡死。

### 根因分析
**不是异步时序问题，是 SwiftUI 布局引擎死锁。**

`ImageProcessingView` 的 body 中有 5 个条件区块（imageFileList、compressionConfigSection、formatConversionSection、executeSection、resultsSection），全部绑定在 `!viewModel.selectedImages.isEmpty` 或 `!viewModel.results.isEmpty` 上。

当 `clearImages()` 同时清空 `selectedImages` 和 `results` 时，5 个区块在同一帧内从 ScrollView 中移除。macOS 的 SwiftUI 布局引擎在处理大量同时移除时死锁，连带导致 NavigationSplitView 导航状态错乱（跳转到历史记录页）。

### 修复方案（3 个文件）
**核心思路**：不清空数组，而是直接替换整个 `@State` ViewModel。SwiftUI 的 `@State` 替换是原子操作，整个视图树一次性重建，不存在多区块逐个移除的布局竞争。

1. **ImageProcessingView.swift**：`viewModel.clearImages()` → `viewModel = ImageCompressionViewModel()`
2. **FileRenameView.swift**：`viewModel.clearFiles()` → `viewModel = FileRenameViewModel()`
3. **ImageCompressionViewModel.swift / FileRenameViewModel.swift**：移除异步两阶段 `clearImages()`/`clearFiles()` 方法（不再需要）

### 技术要点
- `@State` 替换触发 SwiftUI 做整体视图树替换，而非增量移除
- 不需要 `DispatchQueue.main.async` 延迟，不需要 `[weak self]`
- 旧 ViewModel 实例被自动释放，新实例从初始状态开始

  - 格式转换：WAV/AAC/M4A/AIFF/CAF 互转
  - 人声增强：AVAudioEngine + AVAudioUnitEQ 带通滤波（300-3400Hz）
  - 降噪：EQ 高通(80Hz) + 低通(8-12kHz)，三档强度
  - 裁剪：AVAssetExportSession + timeRange + KVO 进度
  - 离线渲染模式：engine.enableManualRenderingMode

### Sprint 3：证件照换底 — 深色衣服误抠 Bug 修复 ✅

**问题现象**：
换白底后，黑色衣服部分区域被误认为背景色，与白色背景融为一体。

**根因分析**：
原图（IMG_6625.JPG）背景是从上到下的蓝→深黑渐变。底部角落像素接近黑色（RGB ~20,28,20），旧算法使用四角 `min()` 曼哈顿距离作为全局背景参考，导致深色背景行的容差阈值过低，深色衣服被连带误判为背景。

**算法演进（3 次迭代）**：

1. **四角 min() → 四边全局色域**（失败）
   - 思路：取四边 5%-95% 分位数作为背景颜色范围
   - 问题：色域太宽，中间调像素可以以很小的距离落入色域，仍然误判

2. **四边全局色域 → 逐行背景建模**（成功）
   - 每行独立采样左右边缘（宽度取 min(20, 总宽/10)），计算该行背景平均色
   - 每像素与**该行**的背景色比较，而非全局背景色
   - 正确处理垂直渐变背景：顶部蓝色行、底部深色行各自有独立的背景参考

3. **新增边缘距离惩罚**（加固）
   - `penalty = edgeDist / maxDim * tolerance * 5.0`
   - 离边缘越远的像素，惩罚越大 → BFS 泛洪更难以泄漏到人物中心
   - 深色衣服像素（距边缘远）颜色距离 + 大惩罚 >> 阈值，安全

**Python 验证结果**：
- 衣服区域像素（行 15%-80%）颜色距离 230-311，远超阈值 70 → 安全
- 底部深色地板（行 85%+）颜色距离接近 0，正确识别为背景
- 边缘 3 像素安全侵蚀 + 5×5 羽化过渡带不变

### 算法核心代码

```swift
// Step 1: 逐行背景建模
for y in 0..<height {
    // 采样该行左右边缘像素，计算该行背景平均色 (rowBgR, rowBgG, rowBgB)
}

// Step 2: 逐像素颜色距离 + 边缘距离惩罚
for y in 0..<height {
    for x in 0..<width {
        let colorDist = abs(r - bgR) + abs(g - bgG) + abs(b - bgB)
        let edgeDist = min(x, width-1-x, y, height-1-y)
        let penalty = edgeDist / maxDim * tolerance * 5.0
        bgDistance[i] = colorDist + penalty
    }
}

// Steps 3-6: BFS 泛洪、安全侵蚀、羽化、alpha 赋值（不变）
```

**算法铁则**：
1. 逐行背景建模 → 每行取左右边缘平均色作为该行背景参考色
2. 逐像素对比该行背景色计算曼哈顿距离 → 泛洪填充"连通到四边"的背景区域
3. 对背景区域做 3 像素安全侵蚀 → 绝不触碰人物
4. 侵蚀掉的 3 像素环 → 羽化过渡带（纯背景侧，向前景渐变）
5. 人物区域 → alpha=255，100% 锁定原图像素
